# Заявки в Telegram

Статичний сайт залишається на GitHub Pages. Worker приймає `POST /booking`
з JSON і надсилає повідомлення через Telegram Bot API. GitHub Actions у цьому
процесі не бере участі.

## Запуск

З кореня репозиторію, Node.js 22+ і pnpm 11:

```sh
pnpm install --frozen-lockfile
pnpm build:phone
pnpm test
pnpm exec playwright install chromium
pnpm test:browser
pnpm worker:check
pnpm exec wrangler login
pnpm exec wrangler whoami
pnpm worker:deploy
```

До налаштування секретів Worker повертає `503`, нічого не надсилає.
Для кількох Cloudflare-акаунтів виберіть потрібний через локальний
`CLOUDFLARE_ACCOUNT_ID` перед розгортанням.

1. Створіть окремого нового бота через BotFather (`/newbot`). Для особистого чату
   найпростіше запустити локально `pnpm telegram:setup` в інтерактивному терміналі.
   Токен вводиться приховано, зберігається лише в пам'яті процесу й у секретах
   Cloudflare. Помічник покаже посилання нового бота з випадковим кодом.
   **Власниця** має відкрити це посилання зі свого Telegram і натиснути Start
   протягом трьох хвилин. Помічник знайде саме цю команду через `getUpdates`
   та запише обидва секрети без показу їх значень. Інші повідомлення не виводяться.
   Бот має бути окремим і без webhook/іншого отримувача getUpdates.
   Якщо використали помічник, переходьте до кроку 4.
   Для групового чату налаштовуйте секрети вручну; додайте бота до групи й дайте
   право надсилати повідомлення.
2. У Cloudflare відкрийте `Workers & Pages → yana-vergun-booking → Settings →
   Variables and Secrets`. Додайте **два Secret**, не звичайні змінні:
   `TELEGRAM_BOT_TOKEN` і `TELEGRAM_CHAT_ID`. Значення вводяться тільки там.
   Chat ID має відповідати потрібному чату, а не username власниці.
3. Альтернатива: інтерактивні команди, значення вводяться в запит CLI,
   ніколи не як аргумент команди:

   ```sh
   pnpm exec wrangler secret put TELEGRAM_BOT_TOKEN --config worker/wrangler.jsonc
   pnpm exec wrangler secret put TELEGRAM_CHAT_ID --config worker/wrangler.jsonc
   ```

4. Поточний Worker уже розгорнуто, його публічна адреса встановлена в
   `BOOKING_ENDPOINT` у `assets/booking-config.js`:
   `https://yana-vergun-booking.yana-vergun-photography.workers.dev/booking`.
   Після перенесення до іншого акаунта встановіть фактичну нову адресу.
5. Закомітьте і опублікуйте зміни на GitHub Pages. На опублікованому сайті
   заповніть форму тестовими даними, позначте коментар як тест і перевірте,
   що повідомлення надійшло саме власниці. Лише після цього інтеграція активована.
   Перевірка опублікованої форми без надсилання:
   `node scripts/check-live-booking.mjs`. Для рівно однієї тестової заявки:
   `node scripts/check-live-booking.mjs --send-test`. Остання команда дійсно
   надсилає повідомлення, не запускайте її багаторазово. Після `ok: true`
   власниця має підтвердити отримання саме в потрібному чаті.

Не публікуйте значення секретів у Git, документації, чаті чи логах. Якщо треба
визначити Chat ID через Bot API, робіть це локально в довіреному середовищі:
URL запитів Bot API містить токен, а відповідь може містити особисті повідомлення.
Не додавайте цей бот до сторонніх сервісів для визначення Chat ID.

Якщо токен потрапив на скріншот або в командний рядок, перевипустіть його через
BotFather для цього самого бота. Оновлення лише токена зі збереженням Chat ID:
`node scripts/setup-telegram.mjs --token-only --bot YanaVergun_bot`.
Помічник перевіряє належність токена вказаному боту. При запуску в окремому
вікні використовуйте `cmd /c`, щоб після завершення не залишався shell prompt.

## Поведінка й перевірки

- Обов'язкові ім'я (до 80 символів) і телефон (до 32 символів до нормалізації).
  Українські номери з локальним нулем, кодом `380` або `+380` нормалізуються
  до E.164. Для інших країн потрібен `+` із кодом країни. Міжнародна перевірка
  використовує `libphonenumber-js/max`; код `+380` не додається до іноземних номерів.
  Браузер і Worker використовують той самий локальний bundle `assets/phone-number.js`.
  Його джерело: `src/phone-number.js`, відтворення: `pnpm build:phone`.
  Instagram: username або HTTPS-посилання на профіль, до 100 символів;
  побажання: до 1500. Перевірки спільні для браузера й сервера.
- Тіло запиту обмежене 8192 байтами, включно з потоковими запитами;
  читання має таймаут 3 секунди. Telegram має таймаут 8 секунд разом із читанням JSON.
- Успіх лише після HTTP-успіху Telegram та `ok: true`.
  При помилці чи таймауті форма зберігається. Автоматичних повторів немає:
  при втраті відповіді Telegram вже міг прийняти повідомлення.
- Honeypot `website`, ліміт 3 запити/60 секунд на IP і 30/60 секунд на сайт.
  Обидва ліміти виконуються сервером через Cloudflare Rate Limiting bindings;
  відсутність binding чи помилка лімітера закриває надсилання.
  Ключ IP хешується, контакти в лімітерах не зберігаються.
- Ліміти Cloudflare приблизні й окремі для кожної локації, не глобальна
  квота. За розподіленого спаму можна додати Turnstile або строгий ліміт через
  Durable Object. CORS і перевірка Origin самі по собі від ботів не захищають:
  небраузерний клієнт може підставити дозволений Origin.
- CORS дозволяє лише `https://teamrisefb-boop.github.io`, `POST`, `OPTIONS`
  і `Content-Type`. Локальний origin у робочому Worker не дозволений.
- Заголовок і назви полів виділяються `bold` entities. Телефон нормалізований,
  в одному рядку, з entity `phone_number`. Offsets і lengths — UTF-16 code units
  (`String.length` у JavaScript). `parse_mode`, `code`, `pre`, `tel:`-кнопки
  й додаткова контактна картка не використовуються.
  Поведінка натискання номера залежить від Telegram-клієнта: перевірте його
  на мобільному Telegram. `sendContact` можна додати окремо як опцію, якщо потрібно.
  Instagram нормалізується до `@username`, `text_link` веде лише на
  `https://www.instagram.com/username/`. Preview вимкнений через `link_preview_options`.
  Порожні Instagram/побажання пропускаються повністю. Час розраховується
  в `Europe/Kyiv`, але показується як `ДД.ММ.РРРР · ГГ:ХХ`, без секунд і технічної зони.
  Тіла запитів/відповідей, винятки й Telegram URL не логуються;
  Workers observability вимкнено. Не підключайте сторонні tail/log-обробники,
  які записують вихідні URL або контакти.

Тести перевіряють підтверджений успіх, невалідні поля, обмеження довжин і тіла,
CORS, honeypot, серверні ліміти, збої Telegram, таймаути, повторне натискання,
UA/EN (включно з перемиканням під час запиту), збереження даних і мобільну форму.
Telegram у цих тестах підмінений. Це не підтвердження реальної доставки.

Worker розгорнуто, його справжню публічну адресу додано у фронтенд. Секрети
записані тільки в Cloudflare, у репозиторії їх немає.
31 жовтня 2026 року тестова заявка з опублікованого сайту пройшла весь шлях:
HTTP 200, Telegram `ok: true`, форма показала успіх і очистилась. Користувач
підтвердив отримання повідомлення в особистому Telegram-чаті. Початкову інтеграцію активовано.

## Група та теми

Параметр призначення — **Secret `TELEGRAM_CHAT_ID`** у наявному Worker
`yana-vergun-booking`. Для групи це її від'ємний числовий ID.
**Secret `TELEGRAM_MESSAGE_THREAD_ID`** необов'язковий: додатний ID теми форуму.
Відсутнє або порожнє значення означає надсилання без прив'язки до теми.
Обидва значення беруться лише із серверної конфігурації: поля відвідувача
`chat_id`, `message_thread_id`, `TELEGRAM_CHAT_ID` ігноруються.
Помилкова конфігурація зупиняє надсилання з безпечним `503`.

Безпечне налаштування групи: `pnpm telegram:group` в інтерактивному терміналі.
Помічник попросить чинний токен приховано тільки для перевірки бота й доступу
до групи. Наявний токен Worker не змінюється.

1. Додайте бота до групи та дозвольте надсилання текстових повідомлень.
   Звичайного членства достатньо; права адміністратора й вимикання privacy mode
   не потрібні. Команда `/start@YanaVergun_bot` не є способом визначення ID.
2. Вставте в приховане поле помічника один із варіантів: точний від'ємний Bot API
   Chat ID; посилання на повідомлення приватної супергрупи `t.me/c/...`;
   посилання на повідомлення публічної групи; адресу відкритої групи
   з `https://web.telegram.org/a/` або `/k/`, якщо її hash містить точний від'ємний ID.
   Посилання-запрошення не підходить. Для звичайної приватної групи без посилань
   на повідомлення відкрийте цю групу в Telegram Web і скопіюйте повну адресу.
   Якщо Telegram Web використовує іншу структуру URL, використайте точний ID
   із вашого наявного обробника; помічник не вгадує ID.
3. Помічник викликає тільки `getMe`, `getChat`, `getChatMember`, перевіряє
   тип чату, відповідність ID, членство та дозвіл надсилання і показує назву.
   Якщо група має теми, можна ввести ID потрібної теми або залишити порожнім
   для загальної стрічки. Коректність/доступність теми остаточно перевіряє
   Telegram під час надсилання; успіх при помилці не показується.
4. Підтвердіть `YES`, лише якщо назва відповідає потрібній групі. Обидва значення
   записуються через `wrangler secret bulk` зі stdin одним розгортанням,
   включно з очищенням старої теми порожнім значенням. Значення не виводяться
   й не записуються в локальні файли/логи. Інші секрети зберігаються.

Груповий помічник **не** використовує `getUpdates`, не передає offsets,
не видаляє/не встановлює webhook і не змінює privacy mode. Тому він підходить
також для бота, чий webhook або polling уже використовує інший обробник.
Старий `telegram:setup` призначений виключно для початкового приватного чату
нового окремого бота; для груп використовуйте `telegram:group`.

Після налаштування виконайте одну тестову заявку з опублікованого сайту
(`node scripts/check-live-booking.mjs --send-test`). Перевірте саме потрібну
групу/тему, вигляд жирного форматування й дії натискання на телефон
у мобільному Telegram. Автоматичні тести перевіряють нормалізацію трьох
українських прикладів, міжнародні номери, поля помилок, UTF-16 з emoji/ZWJ,
захист destination від підміни й відсутність втручання в update-обробники.

31 жовтня 2026 року призначення змінено на потрібну групу через серверний
`TELEGRAM_CHAT_ID`. Після зміни виконано одну тестову заявку з опублікованого
сайту: HTTP 200, Telegram `ok: true`, форма показала успіх. Повідомлення
перевірено безпосередньо в групі через Telegram Web: жирні поля, ім'я з емодзі,
нормалізований телефон-посилання та посилання Instagram відображаються правильно.
Токен не змінювався; webhook, polling і privacy mode не змінювалися.
Користувач підтвердив, що номер натискається у його мобільному Telegram.
Це перевірка конкретного клієнта, а не гарантія однакової поведінки всіх клієнтів.
